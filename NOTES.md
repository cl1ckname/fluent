# Заметки по ходу

## Go-инструменты

- **gofmt переписывает `//@` в `// @`** в doc-комментариях объявлений верхнего
  уровня (переформатирование doc comments с Go 1.19). Не трогаются только
  директивы вида `//word:...` и doc-комментарии полей. Решили держаться за `@`:
  основная форма `// @`, `//@` тоже принимается.
- **gofmt переписывает и блочные doc-комментарии**:
  `/*@ requires ...;\n    returns ...; */` становится
  `/*\n@ requires ...;\n\n\treturns ...;\n*/`. Поэтому блочный комментарий —
  спецификация, если первый непробельный символ после `/*` это `@`
  (сам `@` лексер считает пробельным).
- gofmt выравнивает поля структуры по концевым комментариям. Если у поля
  однострочный `/*@ ... */ // коммент`, выравнивание «плывёт». Ни на что не
  влияет, но выглядит некрасиво.
- `go/scanner` не подходит для лексера спецификаций: `a<c>==b<c>` он разбивает
  на `>=` `=`, а `;` в конце строк вставляет сам (пропущенная `;` прошла бы
  молча). Пришлось написать свой небольшой лексер.
- Узлы `go/ast` нельзя расширить, поэтому знания о спецификациях хранятся,
  как в `types.Info`: в отдельных таблицах с ключами-объектами `go/types`
  (`bound.Info`).

## Язык

- В `returns` нужен `_` для типов, которые грамматика не выражает
  (`[]byte`, `*T`, ...): тип подставляется по позиции из сигнатуры.
- `requires` в v0 сравнивает только индексы (`x<p>`) и константы. Это
  сознательное сужение. Кандидат на расширение — сравнение обычного
  значения с индексом (`a<c> == s`).

## Congruence

- `Join` (слияние веток) точный: считается пересечение двух замыканий над всеми
  термами банка. Класс результата — пара (класс в ветке 1, класс в ветке 2).
  Пересечение конгруэнций над множеством, замкнутым по подтермам, — снова
  конгруэнция, поэтому потерь нет. Цена — O(размер банка) на каждое слияние.
  Общая задача join для congruence (Gulwani–Tiwari–Necula) сложнее, потому что
  там результат может требовать бесконечно многих термов. Мы ограничены
  конечным банком, и это сознательное упрощение.
- В противоречивом состоянии (`"rub" ≈ "usd"`) `AreEqual` возвращает true:
  точка недостижима, и в ней выводится всё. В TASK.md было «всегда false»,
  но тогда код внутри `if "usd" == "rub" { ... }` давал бы ложные ошибки.
- `AssertDistinct` нет: про неравенства мы ничего не знаем. Различны только
  разные константы. Условие `a != b` не запоминается, но если `a ≈ b` уже
  выведено, ветка, где оно истинно, помечается недостижимой (checker, `facts`).

## Обход тел функций (checker)

- **Join теряет факты о термах, которых ещё нет в банке.** На слиянии веток для
  переменной заводится общий терм `m`, но `m<c>` появлялся только при
  последующем использовании, и Join о нём не знал. Лечится тем, что при
  создании `m` сразу заводятся его индексы и поля (`materialize`, глубина 2).
  Это общий предел нашего Join: он точен только на уже существующих термах.
- Факты из правой части `a && b` (например, о результатах вызовов в ней) в
  then-ветку не попадают: правая часть вычисляется на копии состояния.
  Потеря точности, не soundness.
- Индексы стабильны, поэтому указатели для индексов почти бесплатны:
  `p<c>` — это `idx(*p)`, и никакая мутация его не меняет. Дорого обходятся
  только обычные поля: через указатель они читаются как свежие термы.
- Неявное взятие адреса при вызове метода с pointer-receiver (`x.m()`)
  легко пропустить. Без его учёта обычные поля `x` были бы ложно стабильны.

### Известные дыры в soundness (алиасинг)

Проверяется сохранение индекса при записи в поле bounded-структуры (`equals`/
`close`), при `*p = v` и при переприсваивании переменной с взятым адресом.
**Не проверяется** запись bounded-значения в другие места, на которые может
указывать указатель:

```go
s := []amount{{currency: "rub"}}
p := &s[0]
s[0] = amount{currency: "usd"} // объект за p сменил индекс
p.add(amount{currency: "rub"}) // принято, хотя "usd" != "rub"
```

То же для `h.a = x` через указатель, если поле `a` у `holder` не аннотировано.
Строгое правило «любая запись bounded-значения в адресуемое место, кроме
локальной переменной без взятого адреса, обязана сохранять индекс» закрывает
дыру, но запрещает, например, `amounts[i] = newAmount(...)` (старый индекс
неизвестен). Кроме того, `append` может перезаписывать элементы общего
backing array. Это ровно та зона «указатели и алиасинг», что вынесена в не-цели.

- defer-замыкание может поменять именованный результат после `return`.
  Сейчас это не учитывается.
