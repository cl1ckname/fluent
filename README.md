# fluent

Прототип верификатора для Go: индексированные типы, которые проверяются через
равенства (congruence closure), без арифметики и SMT. Статус — pre-alpha,
язык спецификаций ещё меняется.

Спецификация языка — [SPEC.md](SPEC.md), заметки и известные дыры —
[NOTES.md](NOTES.md), исходная постановка — [TASK.md](TASK.md).

## Запуск

```sh
make                    # сборка fluent и fluent-lsp в bin/
./bin/fluent ./...      # как go vet: пакеты, шаблоны
make test               # все тесты проекта
```

Код выхода 3 означает, что найдены диагностики.

## LSP для IDE

```sh
make fluent-lsp         # сборка только LSP в bin/fluent-lsp
```

В LSP-клиенте редактора добавьте отдельный сервер для файлов Go:

| настройка         | значение                                                                            |
| ----------------- | ----------------------------------------------------------------------------------- |
| команда           | абсолютный путь к `bin/fluent-lsp` или `~/.local/bin/fluent-lsp` при наличии ссылки |
| аргументы         | нет                                                                                 |
| транспорт         | stdio                                                                               |
| язык / тип файлов | `go`                                                                                |

Сервер использует `go.lsp.dev/protocol` и работает рядом с gopls. Он публикует
только диагностики с источником `fluent`: подчёркивание места неудачной
проверки и сообщение с причиной. Completion, hover и навигацию предоставляет
gopls. Редактор должен позволять подключить дополнительный LSP-сервер к Go;
способ настройки зависит от его LSP-клиента.

При открытии или сохранении файла проверяется весь его пакет, включая
внутренние и внешние тесты. Учитываются текущие несохранённые буферы открытых
файлов. Ввод сам по себе не запускает анализ: старые диагностики пакета
очищаются и обновляются при следующем сохранении. Закрытие файла удаляет его
буфер; если в пакете остались открытые файлы, пакет проверяется снова.
Диагностики могут появляться и в соседних файлах пакета.

Нужен установленный Go, доступный в окружении процесса сервера. Загрузка
пакетов учитывает `go.mod`, `go.work`, build tags из `GOFLAGS` и остальные
переменные окружения Go. Поддерживаются несколько корней workspace;
при запуске весь workspace не сканируется. Обрабатываются только `file:` URI.

Если синтаксическая ошибка, ошибка типов или загрузки мешает проверке,
fluent очищает старые результаты и сообщает о пропуске через LSP
`window/logMessage` и stderr. Ошибки самого Go показывает gopls.
Межпакетные контракты имеют те же ограничения, что и у CLI.

## Пример

```go
// @ bound <c Currency>;
type amount struct {
	// @ equals c;
	currency Currency
	value    float64
}

// @ returns amount<c>;
func newAmount(c Currency, v float64) amount {
	return amount{currency: c, value: v}
}

// @ requires a<c> == b<c>;
// @ returns amount<a<c>>;
func (a amount) sum(b amount) amount {
	return amount{currency: a.currency, value: a.value + b.value}
}

func main() {
	a3 := newAmount("rub", 42).sum(newAmount("rub", 12)) // OK
	_ = newAmount("usd", 1).sum(a3)
	// cannot prove newAmount("usd", 1)<c> == a3<c> ("usd" vs "rub")
}
```

Краткая справка (подробно — SPEC.md):

| где               | инструкция                           | смысл                                               |
| ----------------- | ------------------------------------ | --------------------------------------------------- |
| структура         | `// @ bound <c T, d U>;`             | индексные параметры типа                            |
| поле              | `// @ equals c;`                     | значение поля — параметр `c`                        |
| поле bounded-типа | `// @ close <c>;`                    | инстанцирует параметры типа поля                    |
| функция           | `// @ requires a<c> == b<c> && ...;` | предусловие, проверяется в месте вызова             |
| функция           | `// @ returns amount<a<c>>, _;`      | индексы результатов, проверяются на каждом `return` |

`x<p>` — индексный параметр значения `x`, `x.f` — поле. В `requires`
сравниваются только индексы и константы. `_` в `returns` — тип из сигнатуры
без уточнения. gofmt переписывает `//@` в `// @` и переносит `/*@ ... */` —
обе формы понимаются.

## Что проверяется

- `requires` в каждом месте вызова, `returns` на каждом `return`;
- инварианты `equals`/`close` в композитных литералах (включая нулевые поля);
- мутации полей, `*p = v` и переприсваивание переменной со взятым адресом
  обязаны сохранять индекс;
- факты из `if` (`==`, `!=`, `&&`, `||`, `!`), ранний выход через
  `return`/`panic`, слияние веток;
- циклы и `switch` — консервативно: меняющиеся в них переменные забываются.

## Ограничения

- **Только один пакет.** Спецификации из других пакетов не видны: типы
  оттуда считаются типами без индексов, а `requires` функций из других
  пакетов **не проверяются**, их результаты имеют неизвестные индексы.
  Экспорт через `analysis.Fact` ещё не сделан.
- **Контейнеры не поддерживаются**: срезы, map, каналы, поля-указатели с
  `close`, `<?>`. Теория — SPEC.md §6a (черновик).
- **Алиасинг**: запись bounded-значения в элемент среза или в
  неаннотированное поле через указатель не проверяется (NOTES.md).
- Нет generics, интерфейсов с контрактами, встраивания, `switch` не даёт
  фактов, нет арифметики и длины (`len`).
- `reflect` и `unsafe` вне гарантий.
- Консервативность: равенство, которое не выводится, — ошибка. Мутация
  поля с `equals` у локальной переменной, адрес которой не брали, сейчас
  тоже ошибка, хотя это безопасно (см. открытые вопросы в SPEC.md §9).
