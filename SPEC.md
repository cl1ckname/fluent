# Язык спецификаций (черновик v2)

## 0. Модель

Индексы типа устроены как параметры generic-типа, только значением параметра
служит **значение**, а не тип. `amount<c>` — это `amount` с зафиксированным
значением индексного параметра `c`.

- Структура **объявляет** индексные параметры словом `bound`.
- Поле связывается с параметрами одним из двух способов:
  - `equals c` — значение поля равно параметру `c`. Тип поля — обычный
    comparable тип, без индексов;
  - `close <e, ...>` — у поля bounded-тип, и его индексные параметры
    замыкаются выражениями `e, ...` (как инстанцирование generic).
- Параметр без `equals` остаётся ghost: во время выполнения его нет,
  он существует только в типе.
- Индекс — свойство текущей версии значения. Пока объект может увидеть
  кто-то ещё, запись обязана сохранять индекс. При исключительном доступе
  индекс можно изменить (§7a): так выражается typestate.

Структуры без `bound` индексов не имеют. Пути к значениям внутри таких
структур (`w.main.currency`, `w.main<c>`) — обычные термы: они отслеживаются по потоку
и версионируются при присваиваниях.

## 1. Форма записи

Спецификации пишутся в doc-комментарии объявления (структуры, поля,
функции) в стиле ACSL: `// @ ...` или `/*@ ... */`. Каждая инструкция
заканчивается `;`. Внутри `/*@ ... */` символ `@` игнорируется, поэтому
строки можно начинать с `@`, как в ACSL.

Основная форма — `// @` с пробелом: gofmt (с Go 1.19) переписывает `//@`
в `// @` в doc-комментариях объявлений верхнего уровня. `//@` тоже
принимается. Блочный комментарий считается спецификацией, если первый
непробельный символ после `/*` — `@`: gofmt переносит `/*@ ... */`
в `/*\n@ ...\n*/`.

```go
// @ bound <c string>;
type amount struct {
    // @ equals c;
    currency string
    value    float64
}

// @ bound <c string>;
type wallet struct {
    // @ close <c>;
    main amount
    // @ close <c>;
    reserve amount
    name string
}

// @ bound <from, to string>;
type rate struct {
    // @ equals from;
    from string
    // @ equals to;
    to string
    k  float64
}

// @ requires a<c> == b<c>;
// @ returns amount<a<c>>;
func (a amount) sum(b amount) amount { ... }
```

## 2. Грамматика

```
// у структуры
bound     := 'bound' '<' pgroup (',' pgroup)* '>' ';'
pgroup    := ident (',' ident)* gotype          // как в Go: <from, to string>

// у поля
equals    := 'equals' ident ';'                 // значение поля ≡ параметр
close     := 'close' '<' term (',' term)* '>' ';'  // инстанцирование типа поля

// у функции / метода
requires  := 'requires' eq ('&&' eq)* ';'
returns   := 'returns' rtype (',' rtype)* ';'
rtype     := gotype [ '<' term (',' term)* '>' ]
           | '_'                                // тип из сигнатуры, без уточнения
ensures   := 'ensures' [guard '==>'] eq ('&&' eq)* ';'
guard     := ident ('==' | '!=') literal        // ident — именованный результат

eq        := term '==' term
term      := ident access*                      // параметр/receiver, затем путь
           | literal                            // литерал или константа Go
access    := '.' ident                          // поле
           | '<' ident '>'                      // индексный параметр
gotype    := ident | ident '.' ident
```

## 3. `bound` — у структуры

- Не больше одного `bound` на структуру. Порядок параметров задаёт порядок
  аргументов в `T<...>`.
- Тип параметра — любой comparable тип Go. Он разрешается в области
  видимости пакета структуры.

## 4. `equals` / `close` — у поля

- У поля не больше одной аннотации.
- `equals p`: `p` — параметр этой структуры, тип поля идентичен типу `p`.
  Факт: `field(x, f) ≈ idx(x, p)`.
- `close <e1..ek>`: тип поля — bounded-тип с k индексными параметрами, типы `e_i` совпадают
  с их типами. В `e_i` можно использовать параметры этой структуры и
  литералы/константы. Факт: `idx(field(x, f), q_i) ≈ e_i`.
- Один параметр может встречаться в нескольких аннотациях. Это задаёт
  инвариант: например, `main` и `reserve` у wallet в одной валюте.
- Параметр, который не упомянут ни в одном `equals`/`close`, — ошибка
  (скорее всего опечатка). Позже станет warning.
- Каждое `equals`/`close` — инвариант структуры. Он проверяется в composite literal
  и при каждом присваивании поля. Запись поля обязана сохранять индекс:
  `w.main = x` разрешено, только если выводится `x<c> ≈ w<c>`. Исключение —
  параметр, который упоминается ровно в одном поле, при исключительном
  доступе (§7a): `a.currency = "usd"` даёт `a<c> ≈ "usd"`. Параметр
  нескольких полей (`wallet<c>`) меняется только записью объекта целиком.
- Незаданные поля в литерале имеют нулевое значение, и инвариант проверяется
  с ним:

  ```go
  w1 := wallet{main: rub, reserve: rub} // OK: w1<c> ≈ "rub"
  w2 := wallet{main: rub, reserve: usd} // ERROR: "rub" != "usd"
  w3 := wallet{}                        // OK: w3<c> ≈ ""
  w4 := wallet{main: rub}               // ERROR: reserve = amount{}, "rub" != ""
  ```

## 5. Термы и доступ к индексам

- `x.f` — поле `f`, `x<p>` — индексный параметр `p` типа `x`. Пространства
  имён раздельные, поэтому поле и параметр могут называться одинаково.
- Путь можно продолжать: `w.main<c>`, `w.main.currency`.
- `>>` в `amount<a<c>>` лексер разбирает как две закрывающие скобки.
- В `requires` сравниваются **только индексы**. Каждая сторона равенства —
  путь, который заканчивается на `<p>`, или константа, и хотя бы одна
  сторона — индекс. `a.currency == b.currency` и `a<c> == s` (где `s` —
  обычный параметр) — ошибки, нужно писать `a<c> == b<c>`.
  Позже, возможно, разрешим сравнивать неиндексное значение с индексом.
- В `returns` и `close` ограничения нет: `returns amount<c>`, где `c` —
  обычный параметр функции, допустимо.
- В правой части `ensures` действует то же ограничение, что в `requires`:
  сравниваются индексы и константы. Кроме того, как в `returns`, индекс
  можно сравнить с параметром целиком (`res<c> == c`): его значение — то,
  что передал вызывающий. Условие `ensures` сравнивает именованный
  результат с константой (`nil`, `true`, литерал, константа Go) и индексом
  быть не может.

## 6. `requires` / `returns` / `ensures` — у функции

- `requires` — предусловие, конъюнкция равенств. Проверяется в точке вызова.
- `returns` перечисляет **все** типы результатов, как в сигнатуре.
  `T<e..>` фиксирует индекс результата. Просто `T` означает, что индекс
  неизвестен (свежий терм). Если `returns` нет, все результаты неизвестны.
- `_` на месте типа означает, что тип подставляется по позиции из сигнатуры,
  без уточнения. Он нужен для типов, которые грамматика не выражает
  (`[]byte`, `map[..]..`, `*T`, `func`).
- Тип в `returns` должен совпадать с типом в сигнатуре.
- `returns T<e_1..e_k>` на позиции `i` — это сахар для
  `\result_i<q_j> == e_j`, где `q_j` — параметры `T`.
- Термы в `requires`/`returns` берутся **в момент входа в функцию**.
- `returns` действует на **каждом** `return`, включая возврат с ошибкой.
  Если индекс результата нужен только на успешном пути, его описывают
  условным `ensures` (ниже), а на ошибочном пути возвращают нулевое значение.
- `returns` проверяется на каждом `return` в теле функции. В точке вызова
  он даёт факты о результате с подстановкой фактических аргументов.

### `ensures`

`ensures` — постусловие о состоянии **в момент возврата**: об индексах
параметров (typestate объекта) и результатов. `returns` описывает типы
результатов, `ensures` — что известно после возврата и при каком возврате.

```go
// @ requires u<s> == StatusActive;
// @ ensures err == nil ==> u<s> == StatusInactive;
// @ ensures err != nil ==> u<s> == StatusActive;
func (u *Account) Inactivate(role string) (err error) { ... }

// @ ensures err == nil ==> res<c> == c;
func parseAmount(c string, raw string) (res amount, err error) { ... }
```

- Без условия `ensures` действует на каждом `return`. С условием — только
  на возвратах, где условие может быть истинным.
- Условие — **ровно один атом** над именованным результатом: `err == nil`,
  `err != nil`, `ok == true`. Так выражается идиома Go «либо результат,
  либо ошибка»: условие — тег, правая часть — что известно в этой ветке.
  Обе ветки описываются двумя `ensures` с противоположными условиями.
  Дизъюнкций, отрицаний формул и условий из нескольких атомов нет: каждая
  клауза — хорновская импликация, и проверка обходится без перебора случаев.
- Правая часть — конъюнкция равенств. Термы в ней берутся **на выходе**.
- Результат, на который ссылается `ensures`, должен быть **именованным**.
  Без ссылок из `ensures` имена не нужны: позиционный `returns amount<c>`
  работает как раньше.
- Несколько `ensures` образуют конъюнкцию клауз.
- `ensures` об индексах параметров-указателей описывает новую версию
  объекта после вызова (typestate, слой прав — `ALIASING_DESIGN.md`).
  Параметр-значение и сам указатель — значения, переданные вызывающим:
  переприсваивание параметра в теле на них не влияет.
- В точке вызова `ensures` говорит только о памяти, на которую аргумент
  указывает точно (известный объект). О прочей памяти факты не
  добавляются.
- Вызов в `go` и `defer` выполняется позже: его `ensures` в точке
  оператора не действует.
- **Ограничение.** Если функция пишет в объект, то после вызова у объекта
  новая версия, и о ней известно только то, что сказано в `ensures`. На
  пути, где условие клаузы ложно, сказать «объект не изменился» нельзя:
  можно только назвать конкретное значение (`err != nil ==> u<s> ==
  StatusActive`), опираясь на `requires`. Снять ограничение могла бы
  ссылка на значение на входе (`\old`), но такого синтаксиса пока нет.

## 6a. Позиции типа и контейнеры (черновик, не реализовано)

> Черновик написан до модели прав (§7a) и опирается на неизменный индекс
> элемента. Сейчас это не противоречит реализации: указатель, положенный
> в срез, map или канал, теряет права, и писать через него зависимые поля
> нельзя. Раздел нужно пересмотреть вместе с контейнерами
> (`ALIASING_DESIGN.md`, §13, «Отложено»).

Правило, как у Go-generics: нельзя написать `type entry struct { a Box }`,
параметр типа обязан быть задан. Так же и у нас:

> Bounded-тип в **позиции типа** (поле структуры, элемент среза, массива,
> map или канала, значение за указателем) всегда замкнут. Индекс задан
> параметрами владельца, константами или (для локальных значений) выведен
> в момент создания. Значений без индекса нет, в том числе пустых
> контейнеров: GADT мы не добавляем.

Следствия:

- Поле bounded-типа без `close` — ошибка (как `Box` без `[T]`). Структура,
  которая хранит `amount`, либо объявляет `bound`, либо замыкает поле
  константой.
- Контейнер bounded-типа сам bounded с теми же параметрами: `[]amount`
  означает `[]amount<c>`, то есть все элементы имеют один `c`. Индекс
  контейнера пишется так же: `s<c>`. Указатель — контейнер из одного
  элемента: `p<c>` — индекс `*p`.
- Разнородная коллекция (суммы в разных валютах) выражается только через
  интерфейсы (`[]any`), как и с generics. Упаковка в интерфейс теряет индекс,
  type assertion возвращает значение с неизвестным индексом.

### Откуда берётся индекс контейнера

| создание | индекс |
|---|---|
| параметр функции `xs []amount` | терм входа `xs<c>`, как у любого параметра |
| результат вызова | из `returns []amount<e>`; без `<...>` неизвестен |
| литерал `[]amount{a, b}` | из первого элемента, остальные проверяются |
| пустой литерал, `make(...)`, `var s []amount`, `new(amount)`* | из аннотации `close` на объявлении; без неё неизвестен |
| `append(s, ...)`, `s[a:b]`, конверсия | тот же, что у `s` |

\* `new(amount)` и `make([]amount, n)` создают нулевые элементы, поэтому без
аннотации их индекс — индекс нулевого значения (`""`). С аннотацией
`close <e>` нужно доказать `"" == e`, иначе инвариант нарушен (как с `w4`).
Для `make([]amount, 0, n)` элементов нет, и индекс берётся из аннотации.

Неизвестный индекс — это не ошибка, а свежий терм: `append(s, rub)` к срезу
с неизвестным индексом не докажет `rub<c> == s<c>`, и сообщение подскажет
добавить `close`.

Аннотация локального объявления — то же `close`, что у поля: она
инстанцирует тип переменной. Термы в ней — параметры функции, локальные
переменные и константы:

```go
// @ close <"rub">;
var s []amount

// @ close <a<c>>;
buf := make([]amount, 0, n)
```

### Операции

| операция | правило |
|---|---|
| `s[i]`, `for _, v := range s` | `s[i]<c> == s<c>` |
| `s[i] = x` | требует `x<c> == s<c>` |
| `&s[i]` | `p<c> == s<c>`, стабильно |
| `append(s, x...)` | требует `x<c> == s<c>`, результат `<c> == s<c>` |
| `copy(dst, src)` | требует `dst<c> == src<c>` |
| `m[k] = x`, `ch <- x` | требует `x<c> == m<c>` / `ch<c>` |

Так закрывается дыра с алиасингом: любая запись в адресуемую память
bounded-типа сохраняет индекс по построению.

Замечание: строго для soundness замкнутость нужна только в адресуемых
позициях (поля, элементы срезов и массивов, значения за указателем). Значения
map и элементы каналов неадресуемы, их можно было бы оставить
разнородными. Выбрано единообразное правило, как у generics.

### Грамматика

`gotype` в `returns` расширяется до типов Go с индексами:
`[]amount<c>`, `*amount<c>`, `map[string]amount<c>`, `[4]amount<c>`.

## 7. Семантика проверки

- Состояние — congruence closure над термами: версии переменных (`x#n`),
  `field(t, f)`, `idx(t, p)`, константы. `field` и `idx` — неинтерпретированные
  функции.
- Разные константы различны. Равенство двух разных констант противоречиво,
  такая точка недостижима.
- `x := e` / `x = e`: создаётся новая версия `x`, и `x#n ≈ term(e)`.
- Composite literal `T{...}`: факты из `equals`/`close` для заданных полей; незаданные
  поля получают нулевое значение (оно известно).
- `if e1 == e2 {A} else {B}`: в `A` добавляется `e1 ≈ e2`. Если `e1 ≈ e2`
  уже выведено, `B` недостижима; иначе в `B` ничего не добавляется.
- `if e1 != e2 {A} else {B}`: симметрично — в `B` добавляется `e1 ≈ e2`,
  а `A` недостижима, если `e1 ≈ e2` уже выведено. Неравенства в состоянии
  не хранятся, проверяется только противоречие в момент входа в ветку.
  Так защитная проверка `if a.c != b.c { return ... }` при
  `requires a<c> == b<c>` не требует доказывать `returns` в мёртвой ветке.
  Если `A` всегда завершается (`return`/`panic`), `e1 ≈ e2` действует
  и в коде после `if`. Поэтому после `if err != nil { return ... }` известно
  `err ≈ nil`.
- `&&` в условии даёт конъюнкцию фактов в then-ветке, `||` — в else-ветке.
- На слиянии веток остаются только равенства, верные в обеих ветках.
- Циклы: переменные, которые в них присваиваются, получают свежие термы без
  фактов. Тело проверяется один раз от состояния до цикла, после цикла
  известно только то, что было до него (консервативно, без fixpoint).
- `switch` — цепочка `if`-`else`. Значения `case` проверяются по порядку:
  `case v` с одним значением добавляет `tag ≈ v`, а следующие ветки и
  `default` получают отрицания предыдущих значений (как ложное условие
  `==`). `case` с несколькими значениями фактов не даёт. `switch` без тега
  разбирает условия `case` как условия `if`. После `switch` сливаются концы
  веток, состояния у `break` (в том числе `break L` из вложенных операторов)
  и путь, где ни одна ветка не подошла, если нет `default`. После
  `fallthrough` следующая ветка начинается и с конца предыдущей, где факт её
  значения неверен.
- `select` и type switch фактов из `case` не дают; ветки сливаются так же.
  `select` без `default` выполняет одну из веток, `select {}` не завершается.
- Внутри функции её `requires` считаются верными.
- Инварианты `equals`/`close` становятся фактами при чтении поля: любое
  значение bounded-типа им удовлетворяет.
- Индексы и зависимые поля объекта (§7a) берутся из текущей версии его
  содержимого. Запись через любой алиас создаёт новую версию, видимую через
  все алиасы. Независимое поле, прочитанное через указатель или у переменной,
  чей адрес взят (явно `&x`, неявно при вызове метода с pointer-receiver, или
  через захват замыканием), каждый раз даёт свежий терм.
- Переприсваивание переменной с взятым адресом — запись объекта целиком
  (§7a). Обычную переменную можно переприсвоить любым значением.
- Ошибочная мутация (не сохраняющая индекс) после диагностики не применяется,
  чтобы ошибки не шли каскадом. Литерал с нарушенным инвариантом получает
  неизвестные индексы.
- В `a && b` правая часть проверяется с фактами из `a`, в `a || b` — с фактами
  из `!a`.
- Замыкания проверяются как отдельные функции; захваченные переменные неизвестны.
- `goto`: на метке забывается всё, что меняется в функции.
- Функции без контракта (а также вызовы значений-функций и методов интерфейсов)
  возвращают значения с неизвестными индексами.
- **Другие пакеты.** Спецификации структур, контракты и сводки (§7a)
  экспортированных функций и методов видны импортёрам: вызов функции другого
  пакета проверяется так же, как вызов своей, а поля чужих bounded-типов
  подчиняются тем же инвариантам. Пакет без спецификаций, который не видит
  bounded-типов (стандартная библиотека, зависимости без разметки), не
  анализируется: вызовы его функций — неизвестные (кроме встроенной таблицы
  для `fmt`, `log`, `errors`).
- **Недоказанный контракт.** Если тело функции с контрактом не прошло
  проверку (любая диагностика в теле), контракт всё равно передаётся
  импортёрам, но каждый вызов из другого пакета получает диагностику
  `contract of lib.New is not proven in its package: lib.go:12: ...`.
  Так проверка потребителя не выглядит успешной, пока она опирается на
  недоказанное обещание.
- **Инициализаторы пакетных переменных** проверяются как тела без
  параметров: вызовы подчиняются `requires`, литералы — инвариантам,
  замыкания проверяются как отдельные функции. Значение уходит в глобальную
  переменную, то есть в неизвестную память.
- Вызов, который по сводке пишет в объект (§7a), даёт новую версию объекта:
  о ней известно только то, что сказано в `ensures`. Вызов, который только
  читает, факты о памяти сохраняет.
- **Неравенство с константой.** Класс congruence может нести множество
  констант, которым он не равен (в частности, «не nil»). Его пополняют
  then-ветка `if x != c` и else-ветка `if x == c`, где `c` — константа,
  а для `nil` ещё `&x`, `&T{...}`, `new(T)`, `errors.New`, `fmt.Errorf`.
  Слияние класса с исключённой константой — противоречие, точка
  недостижима, как при равенстве разных констант. На слиянии веток
  неравенство остаётся, только если оно выводится на обоих путях. Других
  неравенств в состоянии по-прежнему нет.
- Условие, которое не сравнение (`if ok`, `if f(x)`), даёт `e ≈ true`
  в then-ветке и `e ≈ false` в else-ветке.
- **Условие `ensures` известно**, если для `x == c` выведено `x ≈ c`; для
  `x != c` выведено `x ≈ c'` с другой константой `c'` либо, при `c = nil`,
  у класса `x` есть флаг «не nil». **Условие ложно**, если известно
  противоположное.
- **Проверка в теле.** На каждом `return` клауза `ensures g ==> P`
  пропускается, если `g` там ложно; иначе `P` нужно доказать.
- **В точке вызова** клауза без условия сразу даёт факты. Условная клауза
  становится **отложенным фактом**, привязанным к терму результата. Когда в
  какой-то ветке условие становится известным (например, после
  `if err != nil { return ... }` известно `err ≈ nil`), правая часть
  добавляется в состояние. На слиянии веток отложенный факт остаётся, только
  если он есть на обоих путях. Сработавший факт остаётся отложенным: он
  связывает термы конкретного вызова (результат, версии памяти после
  вызова) и верен всегда, поэтому не теряется при слиянии с веткой, где
  условие ещё неизвестно. Более поздние записи в объект создают новые
  версии, и отложенный факт о них ничего не говорит.
- Если равенство не выводится, это ошибка.

## 7a. Объекты и доступ

Правила вывода, сводок и слияния прав описаны в `ALIASING_DESIGN.md` (§11);
он нормативен для этого раздела. Здесь — то, что видит пользователь.

- **Объект (блок)** — память, в которой лежат зависимые поля: значение за
  указателем (`&T{...}`, `new(T)`, параметр-указатель) или локальная
  переменная с взятым адресом. Зависимые поля — поля с `equals`/`close`
  и пути к ним через вложенные `close`-поля. Остальные поля независимые:
  они читаются и пишутся без прав.
- **Права.** Функция держит на каждый объект право: полное, только чтение
  или никакого. Чтение зависимого поля требует права на чтение, запись —
  полного права. Без права — ошибка с причиной, по которой право потеряно.
  Аннотаций прав нет.
- **Потеря прав.** Право теряется, когда указатель уходит туда, где анализ
  его не видит: в глобальную переменную, срез, map, канал, замыкание,
  обычное поле-указатель, неизвестный вызов, горутину. Удержание после
  вызова, утечки и перенос во владеющее поле выводятся из тела вызываемой
  функции (сводка). Вызов, который удерживает указатель, забирает право.
- **Исключительный доступ** — значение, которое видит только функция
  (переменная без взятого адреса), или объект, на который указатель
  указывает точно и на который есть полное право. Только при нём меняется
  индекс:
  - параметр, который упоминается в одном поле, меняется записью этого поля;
  - параметр нескольких полей — только записью объекта целиком
    (`*w = wallet{...}`, `x = ...` для переменной с взятым адресом).
    Пофилдовая запись обязана его сохранять, поэтому инвариант не бывает
    нарушен даже временно.

  Без исключительного доступа (например, указатель может указывать в разные
  объекты на разных путях) запись обязана сохранять все индексы.
- **Владеющее поле** — поле-указатель на тип с зависимыми или владеющими
  полями (`Order.Acc *Account`). Запись адреса в него переносит объект
  в регион владельца: права региона — права корня. У объекта один
  владелец. После вызова, который пишет в регион, `o.Acc` — новый объект,
  а указатели, взятые из региона до вызова, прав не имеют.
- **Ветки и циклы.** На слиянии остаётся меньшее из прав ветвей. Право,
  потерянное в теле цикла, недоступно после цикла; объекты, записанные
  в теле, после цикла неизвестны.

## 8. Диагностики

| Где | Что |
|---|---|
| спецификация | синтаксис; неизвестный параметр/поле; не-comparable тип параметра; несовпадение типов в `equals`/`close`/`returns`; `close` на поле не bounded-типа; неверная арность `T<...>`; неиспользуемый параметр; условие `ensures` не над именованным результатом или не с константой; `!=` вне условия |
| точка вызова | `cannot prove a4<c> == a3<c> ("usd" vs "rub")` |
| импорт | `package X has errors in fluent specifications; some of its contracts are ignored` — в пакете есть и разобранные, и ошибочные спецификации, или спецификация не выражается в факте |
| объявление | `specification of T cannot be exported to other packages` / `contract of F cannot be exported ...` — тип индекса не выражается в факте (инстанцирование generic-типа) |
| вызов функции другого пакета | `contract of lib.F is not proven in its package: <файл>:<строка>: <первая диагностика в теле>` |
| `return` | тело не подтверждает `returns` / `ensures` (с указанием клаузы): `cannot prove ensures err == nil ==> u<s> == StatusInactive`; для функции без результатов — также на закрывающей скобке |
| присваивание поля | мутация не сохраняет индекс там, где обязана (§4, §7a) / нарушает `equals`/`close`: `cannot prove assignment to w.main preserves w.main<c> == c` |
| доступ к зависимому полю | нет права или только чтение, с причиной: `cannot read p.Status: no access: kept by use at line 12 (...)`, `cannot write p.Status: read-only access: ...`; память неизвестна: `... does not point to a known object`, `... is a global variable` |
| передача в вызов | `cannot pass p to f: no access: ...`; `... f may write to it, but access is read-only: ...`; `... the same object is passed more than once and f may write to it` |
| владеющее поле | `cannot store acc in o.Acc: acc already belongs to ...`; `an object cannot own itself`; `... points inside another object`; `... may point to different objects` |

## 9. Вне scope v0 / открытые вопросы

- Указатели и алиасинг решаются моделью прав (§7a). Отложенное в ней —
  извлечение объектов из регионов, указатели в контейнерах, разделяемые
  ссылки, конкурентность, интерфейсы — перечислено в `ALIASING_DESIGN.md`,
  §13, «Отложено».
- Сочетание с Go-generics (`Box[T]` с полем `T`, у которого есть индексы).
- Файлы аннотаций (стабы) для пакетов без разметки: контракты и, возможно,
  сводки чужих функций без правки их исходников. Идея, не спроектировано.
- Комментарий, начинающийся с `// @`, всегда считается спецификацией, поэтому
  `// @since 3.16` в чужом коде даёт синтаксические ошибки. Импортёр о них не
  предупреждается, пока в пакете нет ни одной разобранной спецификации.
- **`<?>`** (синтаксис принят, семантика — черновик): экзистенциальный
  индекс; чтение из `<?>`-позиции даёт свежий жёсткий индекс, сужение — через
  копию в переменную и проверку поля с `equals`. Кандидат: `<?>`-ячейки
  неадресуемы, как значения map.
- **Вариантность** (не решено): можно ли передавать `[]T<c>` туда, где ждут
  `[]T<?>`, и как параметр объявляет, что принимает `<?>`.
- Сужение `<?>` фактами из `switch` (`case "rub":`): сами факты `case`
  есть (§7), связь с `<?>` не проработана.
- Хранение значения индекса в рантайме (наблюдение, NOTES.md): отдельного
  требования не вводим; нужно только, чтобы подсказка «добавь явную проверку»
  не выдавалась, если значение индекса нигде не хранится.
