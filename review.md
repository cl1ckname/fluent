# Замечания код-ревью

Дата: 28 октября 2026 года. Обобщение замечаний из двух проходов ревью и повторной проверки обновлённого диффа.

Шесть замечаний остаются актуальными, одно исправлено. P1 — ошибки, из-за которых проверка может молча принять некорректный код; P2 — остальные ошибки проверки и поведения LSP.

## 1. [P1] Потеря спецификаций для допустимых типов индексов

**Статус:** повторно воспроизведено, не исправлено.

**Место:** [checker/facts.go:244](checker/facts.go#L244), `encoder.typ`; обработка отказов в `Exports.Encode` и декодировании контрактов.

SPEC разрешает любой comparable-тип индекса. Резолвер принимает `any`, `error` и алиас массива, например `type Key = [2]string`, но сериализатор их не поддерживает:

- `any` и массив после `types.Unalias` не являются `*types.Basic` или `*types.Named`;
- встроенный `error` не имеет пакета, необходимого для текущей реализации `objectpath`.

Спецификация структуры молча исключается из факта. Контракты, ссылающиеся на её параметры, затем отбрасываются при декодировании. Ошибки сериализации или предупреждения о потере контракта нет.

Пример:

```go
// Пакет lib.
// @ bound <k any>;
type Box struct {
    // @ equals k;
    K any
}

// @ requires a<k> == b<k>;
func Same(a, b Box) {}

// Пакет-потребитель: равенство индексов не доказано,
// но CLI принимает вызов после потери спецификации.
func F(a, b lib.Box) { lib.Same(a, b) }
```

**Проверка:** временные тесты через `analysistest` подтвердили отсутствие ожидаемой диагностики для всех трёх типов.

**Предлагаемое исправление:** поддержать сериализацию разрешённых типов. Невозможность экспорта доступной потребителю спецификации должна диагностироваться, а не молча ослаблять проверку.

## 2. [P1] Недоказанный контракт зависимости экспортируется без предупреждения потребителю

**Статус:** воспроизведено настоящим CLI; соответствующий код при повторном ревью не изменён.

**Место:** [analyzer/analyzer.go:55](analyzer/analyzer.go#L55), [checker/checker.go:85](checker/checker.go#L85).

После ошибок проверки тела функции её контракт продолжает экспортироваться. Флаг `SpecErrors` отражает только ошибки разбора и разрешения спецификаций. Диагностики зависимости, анализируемой драйвером ради фактов, не показываются при запуске только на пакете-потребителе.

Пример библиотеки с неверным обещанием:

```go
// @ returns Box<c>;
func New(c string) Box { return Box{K: "fixed"} }
```

Если `Same` требует равенства индексов, потребитель может вызвать:

```go
lib.Same(lib.New("a"), lib.Box{K: "a"})
```

Анализ принимает обещание `New`, хотя её реализация возвращает другой индекс.

**Проверка:** `fluent ./use` завершился с кодом 0 без сообщений; `fluent ./lib` сообщил `cannot prove result 1 satisfies returns` и завершился с кодом 3.

**Недокументированное условие:** пользователь должен отдельно проверять все зависимости, контрактам которых доверяет.

**Предлагаемое исправление:** передавать статус неуспешной проверки зависимости и сообщать о нём потребителю. Не представлять проверку как успешную при использовании недоказанных контрактов.

## 3. [P1] Кэш не инвалидируется при изменении API зависимости без аннотаций

**Статус:** воспроизведено в обновлённом LSP, не исправлено.

**Место:** [lsp/analyze.go:247](lsp/analyze.go#L247), построение ключа в `analyzer.state`.

Для зависимости без спецификаций в ключе учитывается версия модуля, но не отпечаток её API. В локальном пакете или модуле через `replace` версия может оставаться прежней после изменения констант, используемых в контракте другого пакета.

Сценарий:

1. В пакете `plain` без аннотаций объявлена `const Currency = "usd"`.
2. Библиотека объявляет `returns Amount<plain.Currency>` и возвращает значение с этой валютой.
3. Анализ потребителя прогревает кэш библиотеки.
4. Константа меняется на `"rub"`, остальные исходники остаются прежними.
5. Потребитель сравнивает результат конструктора со значением `Amount{Currency: "usd"}` через функцию с требованием равенства индексов.

**Проверка:** с прогретым кэшем диагностики нет; с новым пустым кэшем тот же код диагностируется как `"rub" vs "usd"`.

Это противоречит утверждению README об отсутствии устаревших записей кэша.

**Предлагаемое исправление:** учитывать отпечаток API/export data импортов, включая значения констант. Версии модуля недостаточно для локальных и заменённых зависимостей.

## 4. [P2] Ограничение в 20 волн оставляет зависимости без контрактов

**Статус:** воспроизведено в обновлённом LSP, не исправлено.

**Место:** [lsp/analyze.go:160](lsp/analyze.go#L160), условие `wave == 20`.

При холодном кэше обработка длинной цепочки импортов прекращается после 20 волн. Оставшиеся факты недоступны, но анализ потребителя продолжается без сообщения о неполноте проверки.

**Проверка:** построена библиотека и цепочка из 22 пакетов, передающих тип и контракт дальше. При первом анализе вызов с разными индексами принимается без диагностики. При повторном анализе недостающие факты достраиваются и тот же вызов диагностируется.

Результат проверки зависит от истории наполнения кэша. Такое ограничение глубины не описано в документации.

**Предлагаемое исправление:** обрабатывать конечный граф зависимостей до завершения, контролируя прогресс. При невозможности завершить обработку явно сообщать о неполной проверке.

## 5. [P2] Инициализаторы пакетных переменных обходят проверку

**Статус:** воспроизведено; соответствующий код при повторном ревью не изменён. Пробел существовал до рассматриваемого диффа.

**Место:** [checker/checker.go:87](checker/checker.go#L87), сбор и проверка только тел `FuncDecl`.

Инициализаторы пакетных переменных не анализируются. Вызов с нарушенным `requires` проходит без диагностики, хотя идентичный вызов внутри функции диагностируется.

```go
// Same возвращает значение и требует равенства индексов аргументов.
var Bad = lib.Same(lib.Box{K: "a"}, lib.Box{K: "b"})
```

Также остаются без проверки литералы и тела замыканий, расположенные в таких инициализаторах. Документация не исключает эти точки вызова из проверки предусловий.

**Проверка:** временный тест подтвердил отсутствие диагностики на пакетном инициализаторе и наличие диагностики на таком же вызове внутри функции.

**Предлагаемое исправление:** анализировать инициализацию пакета, например в порядке `types.Info.InitOrder`.

## 6. [P2] Событие одного документа сбрасывает несохранённые правки всего каталога

**Статус:** воспроизведено при первом проходе; соответствующий код при повторном ревью не изменён.

**Место:** [lsp/server.go:120](lsp/server.go#L120), [lsp/server.go:166](lsp/server.go#L166), [lsp/server.go:180](lsp/server.go#L180): `DidOpen`, `DidSave`, `DidClose`.

Флаг `dirty` хранится на каталог, но удаляется при событии любого документа этого каталога. Например:

1. Открыты `a.go` и `b.go` одного пакета.
2. Пользователь меняет `a.go`, не сохраняя его.
3. Закрывает `b.go`.
4. `DidClose` удаляет флаг `dirty` каталога и планирует проверку оставшегося файла.

Несохранённый `a.go` больше не защищён от публикации диагностик. Аналогичный сброс происходит при открытии или сохранении соседнего файла. Это нарушает обещание README, что каталоги с несохранёнными правками ждут сохранения.

**Проверка:** временный тест подтвердил, что закрытие `b.go` удаляет признак несохранённых правок `a.go`.

**Предлагаемое исправление:** отслеживать изменённые документы отдельно и выводить состояние каталога из наличия таких документов.

## 7. [P2] Пакеты внутри `testdata` переставали проверяться — исправлено

**Статус:** повторный сценарий прошёл после изменений загрузчика.

В первоначальном варианте LSP заменял загрузку запрошенного пакета `.` на загрузку `./...` от корня модуля. Этот шаблон исключает `testdata`, каталоги с префиксами `.` и `_`. В результате открытие или сохранение файла внутри исключённого каталога возвращало пустые диагностики и очищало предыдущие.

Первоначальный сценарий с пакетом внутри `testdata` воспроизводил пропуск ошибки. После изменений загрузчика тот же сценарий выдаёт ожидаемую диагностику. Исправление повторно проверено именно для `testdata`; отдельные сценарии для каталогов с префиксами `.` и `_` не запускались.

## Валидация

- Штатный `go test ./...` проходит на обновлённом диффе.
- Проблемы, требующие новых сценариев, подтверждались временными тестами; эти тесты удалены после ревью.
- Ошибка доверия недоказанному контракту зависимости дополнительно проверена настоящим CLI.
- Последняя повторная проверка включала потерю типов индексов, инвалидацию кэша по константе, глубину волн и пакет в `testdata`.
- Исходники в рамках ревью не исправлялись.
